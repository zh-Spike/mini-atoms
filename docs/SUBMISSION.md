## 评审须知

- **预览首次加载要几秒**：生成的应用在浏览器沙箱里实时编译，第一次打开需要从 codesandbox.io 加载打包服务，之后会快很多。分享页也一样。
- **Race 耗时取决于最慢的模型**：deepseek-flash 一般 20-40 秒；glm 系列较慢，大一点的应用可能要 1 分钟以上。只想快速看效果可以先不开 Race。
- **模型不可用时会进入演示模式**：如果模型网关连不上或额度用尽，这一轮会自动回放预置应用（看板、番茄钟、记账本），并在对话区提示，流程照常走完。
- **生成的应用数据存在访问者自己的浏览器里**：刷新或重开浏览器后仍在，但换一台设备看不到（平台自身的账号、项目和版本存在数据库里，换设备可见）。
- **两种导出**：「导出」得到 React 项目 zip（`npm install && npm start`）；「HTML」得到单个文件，双击即可打开（需要联网加载 React 等依赖）。

## 开发过程

先交付、后完善：开始后约 2 小时 20 分钟，多智能体生成、预览和 HTTPS 部署就已经上线，之后所有改动都以小 PR 增量合并，每个 PR 跑 CI，合并后自动部署并做线上健康检查。之后依次完成核心闭环和 Race 亮点、稳定性（追踪、国内网络适配、数据库就近迁移）、兜底与交付材料。每个阶段的产出和排障过程见 [AI_WORKFLOW.md](AI_WORKFLOW.md)。

## 做了什么

一句话描述需求，由 AI 智能体团队把它变成一个能直接使用的 React 应用：

1. **输入**：用户在项目页写一句需求，或点示例。
2. **智能体处理**：Mike 判断新建还是修改，Emma 写 PRD，Bob 做架构和文件规划，Alex 写多文件代码，Quinn 做确定性的静态检查，有问题时 Alex 自动修一轮。过程实时流式展示。
3. **运行**：生成的项目在 Sandpack 沙箱 iframe 里编译运行，和主站隔离，可以切换桌面 / 手机尺寸，也可以直接改代码。
4. **持久化**：账号、项目、对话、每个版本都存入 Postgres（Neon 新加坡区域），刷新、换设备都在；生成的应用自身数据存在 localStorage。

亮点做深的是 **Race**：勾选 2-3 个模型，共享同一份 PRD 和架构，并行写代码、各自过检查，分栏实时展示，完成后对比预览、一键采用。在此之上补了对话迭代、不可变版本与回滚、发布成免登录的公开链接、导出 zip，以及完整的调用追踪、用量页、运营后台和公开状态页。

## 关键取舍

- **Sandpack 而不是 WebContainer 或云沙箱**：纯浏览器编译多文件 React，不需要服务端算力和付费沙箱；代价是只能生成纯前端应用。
- **流式 `<file path>` 协议 + NDJSON**：边收边解析，前端能看到"正在写哪个文件"；模型不守格式时有三层兜底（格式提醒、Markdown 代码块解析、带纠正提示的重试）。
- **QA 用规则不用 LLM**：入口、相对引用、依赖白名单、图标名是否真实存在、导入导出是否一致，又快又稳。图标和导入两条是用真实模型实测发现白屏后加的。
- **Race 只分叉写代码这一段**：对比的是同一需求的不同实现，也少跑一次 PRD 和架构。
- **演示模式兜底**：没有 Key 时回放预置应用；线上网关连不上、鉴权失败或额度不足时，本轮自动切过去并提示。演示能否跑完不取决于第三方网关和额度。
- **有意不做的**：不引入 Alembic（表结构简单，启动时补列）、不接第三方可观测平台（表结构按 trace / generation 组织，以后可迁移）、不做多智能体框架。
- **性能**：可观测性上线后发现每轮有大量时间花在数据库往返上，于是把追踪写库改成后台线程，并把数据库从美国迁到新加坡：一轮新建从 22.6 秒降到 14.8 秒，模型调用以外的耗时从约 10 秒降到约 1.5 秒。

## 完成程度

已完成：邀请码注册与账号、多智能体流水线与流式展示、Sandpack 预览、代码编辑、版本历史与回滚、报错一键修复、Race 多模型并行与采用、发布分享与访问统计、导出 zip 与单文件 HTML、移动端适配、调用追踪 / 用量 / 运营后台 / 状态页、演示模式兜底；后端 68 个测试，CI、合并后自动部署和每 30 分钟的线上巡检。

没做 / 已知限制：

- 生成的应用没有后端，数据只在当前浏览器的 localStorage 里
- 预览和分享页依赖 codesandbox.io 的打包服务，网络受限时加载慢
- 生成请求绑定在一个 HTTP 连接上，中途刷新会中断这一轮（已生成的阶段结果和 Race 候选版本会保留）
- 演示模式只预置了三个应用，迭代只支持改主题色和明暗风格
- 不支持图片输入

## 如果继续投入

1. **生成应用的后端能力**：注入平台提供的 KV / 数据表 SDK，让生成的应用数据跨设备持久化（对标 Atoms 的 Supabase 集成），这是和 Atoms 差距最大的一项。
2. **后台任务化**：生成放进队列，断线可以续看，也为多实例部署做准备。
3. **视觉自检**：无头浏览器截图预览，让 QA 基于截图和运行时日志判断，也可以作为 Race 的自动评委。
4. **模板广场与 Remix**、**成本折算与告警**、**基于追踪数据的提示词迭代**。
