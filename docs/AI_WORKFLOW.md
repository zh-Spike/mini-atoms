# AI 协作开发说明

这个项目从第一行代码到上线、排障、文档和演示视频，都是和 AI 编程智能体协作完成的。本文记录用了哪些工具、怎么分工，以及几个由线上数据驱动决策的例子。所有数字都可以在仓库历史里核对（30 次提交、28 个 PR，每个提交都带 `Co-authored-by: Cursor`）。

## 工具链

| 用途 | 工具 |
| --- | --- |
| 编码、重构、写测试、写文档 | Cursor Agent（复杂任务先用计划模式拆解，确认后再执行） |
| 版本管理与评审 | GitHub CLI：每个功能一个分支和 PR，CI 通过后 squash merge |
| 构建与部署 | GitHub Actions：后端、前端、Docker 三项检查；合并到 main 后自动构建镜像、SSH 部署并做 HTTPS 健康检查；每 30 分钟线上巡检 |
| 数据库 | Neon Postgres（Neon MCP 接入 Cursor，用于查看和管理项目） |
| 线上验证、截图、录屏 | Cursor 内置浏览器、Playwright 驱动本机 Chrome |

## 分工

- **AI 负责**：需求拆解和方案草拟、编码、测试、CI 和部署脚本、线上排障（读追踪数据、复现、修复）、截图和录屏、文档初稿。
- **我负责**：选题和方向（做“生成应用的平台”，不做业务应用）、关键取舍的拍板（Sandpack 而不是 WebContainer、QA 用规则不用 LLM、演示模式兜底、不引入 Alembic 等）、生产环境凭证和配置、每个 PR 的验收。

这样分工的原则是：AI 产出快，但方向错了产出越多越浪费。所以每一步先让它出计划，确认后再写代码，写完必须有测试和线上验证才算完成。

## 用数据驱动决策的四个例子

1. **预览样式不生效**（#13、#14）。线上预览没有样式，靠猜很难定位。于是让 AI 在预览里注入探针，把 `<head>`、脚本和计算样式 postMessage 回主页面，发现两个问题：Sandpack 的 react 模板会忽略自定义 `index.html` 的 `<head>`；`cdn.tailwindcss.com` 在国内访问不了。最终改为把 Tailwind 运行时作为本站静态资源，通过 `externalResources` 注入。
2. **模型协议差异**（#12）。同一个网关下，grok 只支持 Responses 协议，glm-5.3 在 Chat 协议下会把思考过程混进正文。逐个模型用真实网关验证后，按模型选择协议，并在遇到 400 时自动降级可选参数。
3. **一轮生成慢在哪**（#16、#17、#21）。先做调用追踪，数据显示三次模型调用只占约一半时间，其余花在数据库往返上（应用在香港、数据库在美国，每次查询约 650 ms）。先把追踪写入改成后台线程，再把数据库迁到新加坡，一轮新建从 22.6 秒降到 14.8 秒。
4. **Race 某一路静默消失**（#26）。录演示视频时发现一路没有产出。追踪数据显示 glm-5.3-flashx 两次调用都是 4096 个输出 token、思考约 1.5 万字符、正文为空：它不接受关闭思考，把整份代码写在思考里，用完了网关默认的输出上限。修复方式是显式设置输出上限，并让没有产出代码的一路明确报错。修复后用同一个需求在真实网关上复现验证。

## 质量保障

- 后端 68 个测试，覆盖解析器、QA、鉴权、额度、流水线、Race、分享、追踪、状态页、演示模式；用假 LLM，不依赖网络
- 生成代码的 QA 用确定性规则：入口、相对引用、依赖白名单、图标名真实性、导入导出一致性
- 第三方 Action 固定到 commit SHA；生产配置放在只对 main 开放的 GitHub 环境里；密钥不进仓库
- 每次部署后通过 HTTPS 校验 `/healthz`、首页、鉴权接口，以及 `/api/status` 返回的版本号等于本次提交
